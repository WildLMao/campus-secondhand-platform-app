## 当前首版的真实起点

- Vue 3 页面使用 HTML/CSS/JavaScript，开发时与 Spring Boot 后端通过 `/api` 交互；构建时前端静态文件进入后端 JAR。分离开发不等于必须分开部署。
- 后端 Java 17、Spring Boot、MyBatis；默认数据库仍为 H2 文件库，已有 MySQL 8.4 Compose 配置。B 的目标是让交付环境明确使用 MySQL，不能只补配置。
- 后端逻辑较集中于 `MarketService.java`、`ApiController.java`，前端集中于 `App.vue`。B 拆后端，C 拆前端；拆分时保持接口和业务行为，避免同时大改规则。
- 已有 H2 集成测试及浏览器走查记录；它们不能替代真实 MySQL、公网、挂载、恢复或性能验证。
- 演示种子默认开启；关闭后空库缺少正式管理员初始化入口。B 提供初始化机制，A 在目标环境验证；不将默认演示账户带入公网交付。

## 修改归属与低耦合边界

| 区域 | 主维护人 | 协作规则 |
| --- | --- | --- |
| Compose、Dockerfile、代理配置、服务器启动及运行环境 | A | 数据库环境变量、健康检查与 B 对齐；应用构建输入与 B/C 对齐 |
| 后端、数据库脚本、接口契约、后端测试 | B | C 核对消费方式；D 核对业务语义 |
| frontend、前端组件、交互及前端测试 | C | 按契约调用接口，不连接数据库，不自行重定义规则 |
| 业务验收场景、独立反例、问题台账及复验记录 | D | 缺陷按归属交原负责人修复，D 独立复验 |

文件主维护权不等于永久禁止其他人修改。跨区域任务先说明影响和交接，避免同一文件并行改写；普通实现细节由负责人处理，不为每次修改重复请求用户批准。

B 维护接口契约，C 共同确认输入输出，D 确认业务含义，A 获取端口、路径和部署依赖。契约至少包括方法、路径、身份/归属、请求、响应、错误码、分页、时间、金额、图片、Session/CSRF 与重复请求语义。

订单状态与占用的联动由统一后端业务入口维护；争议、治理和前端不能分别实现一套订单状态更新。数据库字段变化通过后端接口隔离，公共布局通过组件复用。

## 交接与问题闭环

每人完成可检查的一批工作后，在项目 `docs/handoffs/` 留一份短交接，写清：任务及版本、实际修改、接口/部署影响、运行方法、实际执行的检查和结果、已知缺口、下一位需要接手的事项。不要为了形式重复生成多份报告。

问题进入 D 维护的 `docs/verification/issues.md`，实现阶段编号用 `DEV-D-001` 起顺序追加，避免覆盖需求阶段 V 编号。记录提出、分派、修复版本、原反例复验和关闭依据。建议与阻塞缺陷分开。

有 Git 时使用成员任务分支与 PR；描述本次行为变化、检查及影响。D 是业务验收负责人，不是所有代码修改和所有自测的承担者。B/C 交叉核对接口，A/B 核对部署数据库，D 复验关键规则。没有 Git 时按文件和构建版本完成等价交接，不伪造 PR。

## 完成口径

编译通过、首页打开、模拟断言通过、MySQL 集成通过、公网浏览器通过、恢复通过是不同层次，分别说明。未执行写“未执行”及原因，不能用计划、截图或已有历史结果冒充本轮验证。

实际需求变化由 D 组织确认，说明受影响的 FR/UC/BR/ST 及验收场景，再由对应负责人实现。P2 仍属于本期需求；调整顺序不等于删除范围。不自行新增支付、超时成交、多库存或凭据恢复。

域名、服务器、访问凭据和真实数据由用户指定；缺失时询问具体阻塞项，同时继续可独立完成的本地准备。交接中不记录密码、私钥、令牌或未经脱敏的认证材料。
