# C · Vue 前端与操作体验

先读[共同协作约定](../协作约定.md)和[协作包入口](../../README.md)。本 skill 中的源码、配置及新增 `docs/` 路径均相对包内 `reference-app/`；需求编号以包内 `requirements/documents/软件工程课程需求报告.md` 为准。目标是让普通用户不依赖开发者讲解，也能完成需求中的业务操作。沿用已有校园循环原型的绿色风格，在 Vue 单文件组件中编写 HTML/CSS/JavaScript，不另做原生 HTML 对照项目。

## 输入与实现方式

读取 `frontend/package.json`、`vite.config.js`、`src/App.vue`、`src/api.js`、`src/style.css`、B 维护的接口契约，以及需求的交互、权限和状态说明。正式包中的旧原型提供布局参考，不以其角色切换或内存规则替代真实接口。

将 App.vue 按页面拆分，提取导航、反馈、物品卡片、订单进度和表单弹窗等实际复用组件，集中维护请求和会话逻辑。不要为了拆分引入没有实际需要的状态库或路由层；需要时说明收益并保持既有入口可访问。

开发时使用现有代理访问 `/api`；部署构建继续支持静态文件进入后端 JAR。与 A/B 确认是否改变部署方式，不把 Vite 开发服务器作为公网交付服务。

## 页面任务清单

| 页面/区域 | 需要完成的操作和反馈 |
| --- | --- |

| 我的订单 | 本人买卖身份、成立时快照、当前阶段、允许操作、拒单原因、未交付声明、交付记录、本人收货、提醒、争议入口及终态历史 |
| 消息 | 物品咨询与订单会话区分、双方范围、加载/发送反馈、终态只读、站内通知；发送失败保留输入 |

## 前后端联调约定

- 不直连数据库，不在页面复刻整套交易规则。前端按契约表达状态与允许操作，后端负责最终权限和业务判定。
- 与 B 确认未登录、无权、状态冲突、校验失败、重复结果、处理中、网络中断的区别；错误提示帮助用户决定修改、查询或重试。
- 下单等关键命令同次重试保留原操作标识；内容修正或新意图才使用新标识。不能因网络超时立即换标识重下单，也不能跨账户复用私有回执。
- 401/403 后同步会话；其他标签页退出、换账户或服务重启时清除旧身份的私有页面和缓存。不要自动重放产生业务效果的请求。
- 表单输入、弹窗声明、接口等待与按钮禁用应一致。普通取消与已交付分歧入口分开，不能为方便操作默认勾选事实声明。
- 所有用户文本使用安全渲染；公开页面不含学号、认证材料、私有订单或联系方式。终态与隐藏后的图片读取按后端结果处理。

## 浏览器检查与交接

至少实际走通：新账户认证退回重提、发布审核、检索下单、卖方接单交付、买方确认评价、取消、争议、举报回执、受限旧单和终态消息只读。对应模块未就绪时用清楚标注的开发 mock 并记录缺口，不把 mock 通过算联调成功；交付构建移除 mock 入口和硬编码演示身份。

检查电脑和手机宽度的表单、导航、弹窗、长文本和图片，保证标签、键盘焦点、反馈和必填校验可用。测试断网/超时、重复点击、空数据、无权限和输入错误，保留能安全保留的输入。

交付可构建的前端源码、实际页面与接口对应关系、浏览器走查结果和截图，以及未接通接口清单。B 修复后端后由 C 复查页面，D 再核对业务结果；构建成功不能替代浏览器实际操作。
