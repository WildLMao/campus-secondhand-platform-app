原型按需求报告的核心交易用例构建，覆盖下单、交付、取消、争议和账户限制。验收标准见需求报告7.1，C程序与页面记录见E-C-03—06，D独立复核及反例结果见E-D-05—07。

实现：新意图下单与快照、已有回执/处理中、模拟丢响应及通知失败、接单拒单、交付登记与买方确认、取消声明和先后冲突、争议受理/继续/异常终止、账户限制与隐藏、旧单沟通及终态反馈。

不实现：注册登录认证、发布审核完整流程、搜索收藏、评价完整流程、真实举报审核、统计报表、核实后重发、真实认证授权、持久化、通知服务、支付、后台并发、性能和部署。种子数据代表已审核物品；不存在的能力不算验证通过。

本原型公开列表只展示可交易物品；交易中的物品不进入公开交易列表，交易当事人及授权管理者可查询。争议受理期间暂停接单、拒单和交付登记，保留查询、旧单沟通及补证；已登记且待买方确认时，买方本人仍可确认收到。继续履约结案后按原阶段恢复操作。成员D于2026年10月26日确认沿用此口径，已同步BR19及表5-1，V-C-01/03的处理见[E-D-07](../verification/问题处理与复核.md)。本轮只更新说明，原型代码及历史结果未改动。

## 打开与操作

1. 用当前Edge或Chrome打开[原型入口](index.html)。不需要安装依赖或联网。
2. 初始身份为买方甲；一件模拟教材I01，价格35元（仅测试数据，不是业务阈值），卖方已认证。
3. 点击确认下单；切换卖方，在我的订单接受、登记交付；切换买方甲确认收到。
4. 展开验证工具，可重置、设置响应丢失/暂缓处理/通知失败，或查询本人上一操作。切换身份不是权限隔离或真实登录。
5. 每个场景先重置；重试使用“查询/重试本人上一操作”，修正输入后提交生成新意图。下载走查记录后补充实际观察者和场景号，不直接将下载动作算成人工验收。

角色：buyer买方甲、buyer2买方乙、seller卖方、admin管理员、guest访问者、unverified未认证。后台数据、回执、故障设置及日志仅供模拟观察；生产应用不得照搬角色切换和验证面板。

## 可重复检查

安装Node.js后运行：`node attachments/prototype/verify.cjs`。输出写到attachments/verification/revision-20261022/程序验证结果.json，覆盖同名当前结果；正式证据归档前请先保留旧版本。

页面检查脚本：`node attachments/prototype/browser-check.cjs`，需要Playwright及Edge；通过环境变量C_NODE_MODULES指定包含playwright的node_modules目录，通过C_BROWSER指定浏览器。实际使用Node v24.19.0与Edge版本见页面结果JSON。无该环境时仍可按场景手动操作原型。
