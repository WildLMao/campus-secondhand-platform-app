## 2. 实际修改

### 数据库改为仅使用 MySQL（无 H2 运行方式）

- `backend/src/main/resources/application.yml`：默认数据源改为 MySQL 8.4（`DB_URL`/`DB_HOST`/`DB_PORT`/`DB_NAME`、`DB_USER`、`DB_PASSWORD`，显式 `com.mysql.cj.jdbc.Driver`），连接参数固定 UTC；`Hikari` 保持 `READ_COMMITTED`。**MySQL 连接失败直接启动失败，不提供其他数据库回退。**
- H2 运行配置与数据已全部删除（2026-10-29 追加）：不再有 `application-h2.yml`、不再有可用 profile，`backend/data/campus.mv.db` 已清理；`h2` 依赖降为 `test` scope，仅供自动化测试，不进入交付 JAR。
- `DEMO_SEED` 默认值改为 `false`；`start.ps1` 只启动当前 JAR，不注入任何 profile，未配置变量时按默认 MySQL 连接并提示。
- `compose.yml`：MySQL 固定 `utf8mb4` / `utf8mb4_0900_ai_ci` / UTC；`DEMO_SEED` 默认 `false`；新增 `BOOTSTRAP_ADMIN_*`、`SESSION_COOKIE_SECURE` 透传；应用新增 `/api/health` 健康检查；两个服务 `restart: unless-stopped`。
- `.env.example`：补充初始管理员、Cookie Secure 与交付说明；`.env` 仍被忽略。

### 版本化迁移（替换启动时 CREATE TABLE IF NOT EXISTS）

- 删除 `backend/src/main/resources/schema.sql`。
- 新增 `db/migration/V1__baseline.sql`（空库基线）与 `V2__indexes.sql`（列表、订单、占用、治理与统计索引），规则见 `db/migration/README.md`。
- 新增 `SchemaMigrator`：启动时按 `V{n}__描述.sql` 顺序执行未应用脚本，记录 `schema_migrations(version,description,checksum,applied_at)`；已执行脚本被修改会拒绝启动；MySQL 环境额外核对并记录字符集、排序规则与隔离级别（不一致只告警，不静默修改）。

### 初始管理员

- 新增 `AdminBootstrap`：没有管理员时按 `BOOTSTRAP_ADMIN_USERNAME`/`BOOTSTRAP_ADMIN_PASSWORD`/`BOOTSTRAP_ADMIN_NICKNAME` 创建一个已认证管理员并写审计记录；不覆盖已有管理员、不打印密码、拒绝演示密码与弱密码。
- 关闭演示种子且没有管理员凭据时**启动失败并给出配置说明**，避免交付出无法管理的空库。

### 接口与模块

- 拆分 `ApiController` 为 `AuthController`、`ItemController`、`OrderController`、`CommunityController`、`AdminController`，`AssetController` 改用共享 `SessionSupport`；路由与方法未变。
- `MarketService` 仍是订单阶段与占用联动的唯一事务入口（BR09/BR19 要求统一入口），未拆散状态转换。
- 新增 `HealthController`（`GET /api/health`，返回状态、数据库类型、已应用迁移版本，不含连接串/凭据）。
- 新增接口契约：[`docs/api/README.md`](../api/README.md) 与 [`docs/api/openapi.yaml`](../api/openapi.yaml)。
- 新增数据库说明：[`docs/database/mysql.md`](../database/mysql.md)；本机 Windows 切换与误操作防护见
  [`docs/database/本机MySQL配置避坑指南.md`](../database/本机MySQL配置避坑指南.md)。

### 后端修复与防御（MySQL 严格模式相关）

- 管理员说明按列宽截断（`items.reason`、`verifications.reason` 1000 字；通知 1000 字），不再因超长写库失败。
- 举报 `event_ref` 限 100 字；争议/举报证据限 5000 字且 UTF-8 ≤60000 字节；争议补证累计超限时拒绝。
- 订单 `completed_at` 显式 `jdbcType=VARCHAR`，避免空值在不同驱动下的类型歧义。
- `ErrorAdvice` 将行锁等待超时/死锁映射为 409「本次未生效，请刷新后按原意图重试」，失败事务整体回滚、不重用。
- 退出登录不再为匿名请求创建会话。

## 3. 接口与部署影响

- 接口路径、请求字段、响应字段与错误语义保持兼容；前端无需改调用方式。新增 `/api/health` 供 A 做容器/代理健康检查。
- C：`docs/api/README.md` 已写明 Session/CSRF、`Idempotency-Key`、分页、金额、时间、图片可见性、状态枚举与管理操作字段，可按此核对 `frontend/src/api.js`。
- A：`compose.yml` 现要求 `.env` 中提供 `DB_PASSWORD`、`MYSQL_ROOT_PASSWORD`、`BOOTSTRAP_ADMIN_USERNAME`、`BOOTSTRAP_ADMIN_PASSWORD`；HTTPS 交付设 `SESSION_COOKIE_SECURE=true`；应用健康检查为 `GET /api/health`。
- 时间列仍为 UTC ISO-8601 字符串（`VARCHAR(35)`），未改为 `DATETIME`：业务统计按字符串左闭右开比较，固定格式下等价于时间比较，避免会话时区隐式换算；已加索引并在契约中固定口径。
- 未引入新依赖（未使用 Flyway/Actuator），迁移与健康检查均为项目内实现。

## 4. 运行方法

本地启动（MySQL；应用无其他数据库模式）：

```powershell
cd reference-app
powershell -ExecutionPolicy Bypass -File build.ps1

$env:DB_URL='jdbc:mysql://127.0.0.1:3306/campus?useUnicode=true&characterEncoding=UTF-8&connectionTimeZone=UTC&forceConnectionTimeZoneToSession=true&allowPublicKeyRetrieval=true&useSSL=false'
$env:DB_USER='campus'; $env:DB_PASSWORD='<密码>'
$env:DEMO_SEED='false'
$env:BOOTSTRAP_ADMIN_USERNAME='ops_admin'; $env:BOOTSTRAP_ADMIN_PASSWORD='<强密码>'

powershell -ExecutionPolicy Bypass -File start.ps1    # 后台运行，日志在 .runtime\server.log
# 或前台：java "-Dfile.encoding=UTF-8" -jar backend\target\campus-market-1.0.0.jar
```

建库与账号步骤见 `docs/database/mysql.md`，常见误操作见 `docs/database/本机MySQL配置避坑指南.md`。

真实 MySQL 集成验证（需要 MySQL 8.4 测试库，库名必须含 `test`）：

```powershell
$env:IT_DB_URL='jdbc:mysql://127.0.0.1:3306/campus_test?...'; $env:IT_DB_USER='campus'; $env:IT_DB_PASSWORD='<密码>'; $env:IT_ADMIN_PASSWORD='<强密码>'
cd backend; mvn test -Dtest=MarketMySqlIT
```
