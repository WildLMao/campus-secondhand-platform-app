## 复核时发现并纠正的集成问题

1. 通知接口直接读取 Spring 代理对象字段，空指针被捕获后跳过补投。改为构造注入通知组件，并通过真实 Controller 故障恢复测试验证。
2. 通知失败设为 FAILED 后无法重试、固定通知事件键阻止合法举报复核。改为保留失败原因和次数并轮转补投，每次独立处置采用其事实标识。
3. 登录改变身份世代后无法解除忙碌状态；弹窗嵌套忙碌保护跳过业务请求；首次幂等请求被误判取消；下单回调缺操作者变量。修正后用真实页面完成交易，并检查实际请求数量和标识。
4. 单行输入无法实现 Shift+Enter 换行；补证保存后页面未展示；长通知截断了定位标识。均通过实际页面或 HTTP 复核后才列入通过项。

## 使用与限制

- 数据库日常启动见 [数据库启动核查](数据库启动核查-20261105.md)。MySQL 是独立服务，首次建库、建账号之后，无需每次重新执行建库 SQL；`start.ps1` 启动的是 Java 应用。
- 更新代码后应重新构建。当前 `start.ps1` 只在 JAR 不存在时构建，已有旧 JAR 时不会自动重新打包。
- 完整争议决定保存在 `disputes.decision` 和处置事实中；订单的 `reason` 为最多 1000 字摘要，通知为更短摘要，应从“我的订单”的履约争议查看全文。
- 通知补投由业务提交后或读取通知触发，没有引入后台队列或定时任务；长期没有请求时，失败记录等待下一次触发。
- 成交统计读取已完成订单后做精确时间过滤，适用于当前课程规模；没有把本轮验证包装为大规模性能测试。
- 未实测 MySQL 8.4、另一台真实设备的局域网访问、公网 HTTPS、生产容量或长期运行。浏览器内合成按键检查不等于实机中文输入法的全面兼容测试。
- 本轮所有交易、账号、证据内容及截图均为隔离库中的合成测试数据。
- 复核结束后已停止本轮临时应用和专用 MySQL 容器，保留代码、证据及测试数据；未停止其他已有服务。
