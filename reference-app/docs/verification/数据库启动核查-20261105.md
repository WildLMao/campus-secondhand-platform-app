# 数据库启动核查

本轮基于 `36bf02ae9d2e3d9734cb3a46e0c131338a081b3d` 检查。

## 结论

当前应用运行时依赖独立的 MySQL 服务。`start.ps1` 负责启动 Java 应用，不负责安装或启动 MySQL；`stop.ps1` 也只停止应用。数据库连接失败会导致应用启动失败，当前版本不会切换到 H2。

“需要命令行启动数据库”并不是每次都要重新建库。需要区分以下事项：

1. **首次配置**：安装 MySQL，创建应用数据库、应用账号并授权；空库首次启动还需要初始管理员配置。
2. **日常启动**：确保 MySQL 服务已经运行，向应用提供连接配置，再运行 `start.ps1`。表结构迁移由应用启动时自动执行。
3. **代码更新后**：先重新构建，再启动。现有 `start.ps1` 仅在 JAR 不存在时构建，不会自动判断代码是否比旧 JAR 更新。

## Windows 日常操作

若 MySQL 已注册成 Windows 服务，可以在“服务”管理器中启动，并将启动类型设为自动。也可在有权限的 PowerShell 中先确认实际服务名：

```powershell
Get-Service *mysql*
# 仅当实际服务名称为 MySQL84 时使用以下命令；请按上一条结果替换。
Start-Service MySQL84
```

配置数据库连接的方式沿用 `docs/database/mysql.md`。`DB_URL` / `DB_HOST` / `DB_PORT` / `DB_NAME`、`DB_USER`、`DB_PASSWORD` 应指向同一实例和已授权账号。密码只保存在本机配置或进程环境中，不提交 Git。

首次空库采用正常运行模式时，设置 `BOOTSTRAP_ADMIN_USERNAME`、`BOOTSTRAP_ADMIN_PASSWORD`（至少 12 位且含字母和数字）、`BOOTSTRAP_ADMIN_NICKNAME`。`DEMO_SEED=true` 仅用于独立演示库，会创建固定密码的演示账号，不应用在正式运行库。

在 `reference-app` 目录执行：

```powershell
# 更新代码后，先构建；需要 Java 17+、Node.js 20.19+ 和 Maven。
.\build.ps1
.\start.ps1 -NoBrowser
Invoke-RestMethod http://127.0.0.1:18080/api/health
```

健康检查应返回 `database: MySQL`、`status: UP`；迁移版本应与当前代码中的迁移文件一致。应用日志在 `.runtime/server.log` 和 `.runtime/server-error.log`。只看到网页能打开，不能代替确认数据库连接和迁移成功。

## 本轮测试环境边界

主审为本轮创建了独立 Docker 容器 `campus-review-20261105`，数据库只绑定本机 `127.0.0.1:13307`。使用本机已有的 **MySQL 8.0.39** 镜像，测试库与演示运行库分开；没有使用或改动其他已有数据库的数据。

仓库文档标注 MySQL 8.4；本轮真实运行检查的版本是 8.0.39，因此不能据此宣称已经验证 8.4。正式部署使用的具体版本仍应再做集成检查。
